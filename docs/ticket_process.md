# 星河云平台工单处理规范

> 文档编号：SUPPORT-TICKET-2026-03  
> 生效日期：2026-03-15  
> 适用范围：星河云平台标准版和专业版客户  
> 维护部门：客户支持中心

## 1. 工单等级至关重要

| 等级 | 定义 | 首次响应目标 | 更新频率 |
|---|---|---:|---:|
| P1 | 核心服务整体不可用，影响多个租户 | 15 分钟 | 每 30 分钟 |
| P2 | 主要功能异常，但存在临时绕行方案 | 1 小时 | 每 2 小时 |
| P3 | 个别用户问题、咨询或一般缺陷 | 4 个工作小时 | 每个工作日 |

## 2. 创建工单

2.1 工单至少应包含租户 ID、受影响功能、发生时间、错误现象和联系人。

2.2 缺少租户 ID 的请求可以先创建为“待补充”状态，但不能直接进入 P1 或 P2 的处理队列。

2.3 支持人员不得把密码、访问令牌、银行卡号或其他敏感信息写入工单正文。发现敏感信息时，应立即遮盖并通知提交人通过安全渠道提供。

## 3. 状态流转

```text
新建 → 已受理 → 调查中 → 待客户确认 → 已解决 → 已关闭
                         └→ 挂起（等待外部依赖）
```

3.1 只有值班负责人可以把工单等级从 P2 提升为 P1；降级需要记录原因和时间。

3.2 “待客户确认”状态超过 3 个自然日没有回复时，支持人员可以发送一次提醒；再次超过 2 个自然日仍无回复，才可以关闭工单。

3.3 已关闭工单不能直接恢复为“调查中”。如果客户在关闭后 7 个自然日内补充同一问题的新证据，应重新打开原工单并保留原关闭记录；超过 7 个自然日，应创建新工单并关联旧工单。

3.4 “挂起”只用于等待客户、供应商或网络运营商等外部依赖，不得用来掩盖内部处理超时。挂起时必须填写等待对象和预计恢复时间。

## 4. 处理与升级

4.1 P1 工单应在首次响应后立即通知值班负责人和技术负责人，并建立内部协作群。

4.2 经过 30 分钟仍未定位 P1 根因时，应先发布影响范围和临时缓解措施，不得为了等待完整根因而停止同步。

4.3 涉及数据删除、权限变更或生产配置修改的操作，必须经过双人复核；语言模型生成的建议不能替代复核。

## 5. 关闭标准

5.1 关闭工单前必须填写根因、处理动作、验证结果和客户确认记录。

5.2 仅发送“问题已修复”而没有验证结果的，不满足关闭标准。

5.3 同类问题在 30 天内重复发生 3 次以上，应创建问题单进行根因分析，而不是只逐单关闭。
