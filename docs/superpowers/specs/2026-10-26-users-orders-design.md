## 本次交付

沿用 FastAPI、SQLAlchemy async、MySQL 和现有原生网页，构建办公打印机售后业务。用户注册、登录，查看自己的订单和设备，创建及查询工单；管理员录入订单、登记设备、处理工单、维护知识资料。工具访问同一业务服务和真实数据库，调试页直接执行工具。

完整 LLM 对话循环、任务检查点与恢复留给后续 Agent 学习。当前不扩展购物车、支付、库存、物流、短信或邮件通知。订单来自管理端录入。业务幂等记录负责防止重复写入，不承担 Agent 任务恢复。

## 架构与调用链

```text
业务页面 → 认证依赖 → 业务服务 → MySQL
工具调试页 → 认证依赖 → ToolRuntime → 工具适配器 → 同一业务服务
知识检索工具 → 开放资料范围校验 → 现有检索能力 → Elasticsearch
```

同一个 FastAPI 应用，不拆 Java 服务，不引入新的任务队列。现有 RabbitMQ 继续服务离线建库。运行身份由后端登录态提供；模型参数和调试页参数均不能指定用户身份或权限。

## 身份与权限

- 公开注册只能创建 customer；用户名规范化后唯一，密码使用 Argon2 哈希，不存明文。
- admin 由受控命令创建，交互输入密码；没有默认密码，也不把第一个公开注册者自动变为管理员。
- 使用服务端会话：客户端持有随机令牌，数据库只存令牌摘要。会话固定有效期 8 小时，退出撤销；停用用户立即失去权限。
- Cookie 使用 HttpOnly、SameSite=Lax，生产 HTTPS 使用 Secure。写请求验证 CSRF 令牌与来源；登录、注册也检查来源，拒绝跨站表单调用。响应不缓存身份与业务数据。
- 登录失败使用统一提示。限速计数使用共享数据库，账户与来源分别限制并考虑并发；不把单进程内存字典当成多实例限速方案。生产入口的 HTTPS 和代理配置在部署前检查，此轮文档不改环境配置。
- customer 只能读取自己的订单、设备和工单。admin 可以分页查找客户、录入订单、登记设备、处理工单。工具调用也必须通过相同资源权限检查。
- 现有知识库、文档、模型配置、检索及检索实验管理接口要求 admin。普通用户通过新增的售后知识入口检索明确开放的文档。检索实验保留本机边界并叠加身份校验，实验归属绑定登录用户和会话。
- 未登录返回 401，无功能权限返回 403；普通用户查询不存在或不属于自己的订单统一返回 404。

## 数据库范围

原草案的四张表不足以覆盖设备、工单、共享限速和写入幂等。完整方案新增十张表，字段、约束、索引及迁移边界见计划书。所有时间统一使用 UTC，日期型保修期限按约定业务日期计算。

| 表 | 职责 |
| --- | --- |
| business_users | 用户、密码哈希、角色、启停状态 |
| auth_sessions | 可撤销的服务端登录会话 |
| auth_rate_limits | 登录注册限速的共享计数 |
| orders | 用户所属订单及金额 |
| order_items | 产品型号、数量、单价与明细金额 |
| devices | 唯一设备编号、型号、固件、订单关联和保修日期 |
| tickets | 用户所属工单、设备、问题描述与当前状态 |
| ticket_events | 工单处理记录和状态变更历史 |
| business_operations | 写入操作的幂等键、参数指纹和结果凭据 |
| support_knowledge_documents | 明确向售后用户开放的型号与知识文档关联 |

订单金额由后端计算；设备归属必须匹配订单；工单归属从设备推导，不能由调用者伪造。同一操作键重复创建工单返回同一结果，参数不同则拒绝。工单写入、初始记录与幂等成功结果在同一事务提交。

提供可审阅的增量建表脚本和只读校验。启动不自动迁移新业务表。保留现有数据及离线建库 tasks；新表清单与实际执行目标库在迁移前核对。当前授权仅为文档，未执行 SQL。

## 页面与工具

- 用户页面：身份入口、订单、设备、工单、售后知识、工具调试。
- 管理页面：客户查找、订单录入、设备登记、工单处理、资料开放管理；复用现有知识库和模型配置页面。
- 工具：list_orders、query_order、list_devices、query_device、list_tickets、query_ticket、create_ticket、search_knowledge。
- 调试页展示工具说明、参数、当前身份、Observation、耗时和实际尝试次数。创建工单是真实写入；用户明确点击提交后执行，超时后先查原操作结果。

## 数据与资料

复用仓库现有“澄印 NX100/NX200”虚构打印机资料体系。准备 1 个管理员、3 个客户、12 笔订单、18 台设备、12 张历史工单，覆盖不同归属、保修期内外及工单状态。初始化可重复运行，不重复插入或覆盖用户后续维护的数据，不提交默认密码。

原始设备 fixture 仅作参考；工具必须查询数据库。公开手册与故障资料经过开放清单进入真实检索链路，历史工单文档默认不公开；评测题及判定要求禁止入库。资料与业务数据明确标注为合成练习数据。
